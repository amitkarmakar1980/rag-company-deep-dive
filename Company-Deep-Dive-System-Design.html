1. Executive Summary

Company Deep Dive Engine is an AI-powered interview decision-support tool for senior product, strategy, and GM candidates (Director / VP+ level). Rather than generic research, it answers a single question:

"Should you pursue this role — and if so, how do you win the interview?"

The system combines multi-tier LLM reasoning, retrieval-augmented generation (RAG), persona-aware report construction, and explicit quality gates to produce deeply contextualized, evidence-backed interview preparation briefs.

4. Pipeline Phases & Data Flow

4.1 Phase Overview

PhaseStatus ShownDurationKey Operations
Validationpending<100msInput sanitization, auth, company lookup/create
Source Planningfetching_sources2–5sLLM research planner → selects 10 sources
Web Fetchfetching_sources20–40sFirecrawl × 8-15 sources (concurrency = 3)
Clean & Chunkfetching_sources2–5sHTML strip, semantic chunking (~500 tokens), dedup
Embeddingfetching_sources5–10sOpenAI text-embedding-3-small (1536 dims, batched)
Vector Storagefetching_sources1–2sBulk insert to Supabase pgvector
Report Synthesisgenerating_report30–60sParallel: o3 synthesis + gpt-4o-mini quality gate
Overlay (optional)completed10–20sgpt-4o personalization from resume

Total end-to-end: 60–120 seconds from form submission to "completed" status.

4.2 Ingestion Sub-Pipeline Detail

  • Stage 1 — Source Planning: LLM planner selects ≤10 URLs — careers, newsroom, blog, investor, press, leadership, about, product, developer, custom pages. Targets ≥5 external sources beyond company domain.
  • Stage 2 — Web Fetch: Firecrawl v2 scrape API (axios fallback). Extracts markdown + HTML; resolves redirects; classifies source type; stores raw content.
  • Stage 3 — Cleaning: Strip HTML tags, boilerplate, and navigation elements; normalize whitespace; compute SHA256 content hash for deduplication.
  • Stage 4 — Chunking: ~500-token semantic chunks with 50-token overlap; token count calculated per chunk.
  • Stage 5 — Embedding: OpenAI text-embedding-3-small, 1536 dimensions; batched for cost efficiency.
  • Stage 6 — Storage: Bulk insert to sources → chunks → embeddings tables; IVFFlat pgvector index enables fast cosine search.

Typical result: 30–100 chunks across 8–15 sources per request.

6.2 Deep Analysis Prompt (Legacy / Baseline)

AttributeValue
Filelib/ai/prompts.ts → getDeepAnalysisPrompt()
Modelo4-mini (deep reasoning)
PhasePhase 2 — Report Synthesis (legacy route)
PurposeGenerate SWOT analysis, strategic positioning, and risk assessment
InputRetrieved evidence chunks [1]…[N], company metadata, role metadata, optional profile context
Output SchemaJSON: { company_swot, role_swot, strategic_bet_analysis, why_role_exists_now, risks_red_flags }
Tone / PersonaSenior strategy firm engagement manager (McKinsey/Bain equivalent)

Reasoning Framework (6 Layers)

  • Layer 1 — Source Reliability Audit: classify each source as company-authored, third-party, or user-supplied
  • Layer 2 — Competitive Position Mapping: Porter's Five Forces + value chain analysis
  • Layer 3 — Org Health Signals: leadership changes, hiring patterns, reorg signals
  • Layer 4 — Strategic Inflection Point Detection: what changed in the last 12–18 months?
  • Layer 5 — Fact / Inference / Hypothesis Tracing: every claim explicitly labeled
  • Layer 6 — Stress Test: specificity check, named-signal check, circularity check

Quality Standards: Specificity over completeness. No category-level risks. Anti-hallucination. Prefer omission over invention.

  • Step 1 — Input Classification: classify resume, JD, and base positioning by reliability
  • Step 2 — Coverage Map: expertise, scope, leadership, metrics, trajectory, gaps

  • Step 4 — Fact / Inference / Hypothesis Separation: explicit labeling

  • Be direct about genuine gaps; do not minimize or ignore them
  • Empty proof_points acceptable; fabricated proof points are NOT acceptable
  • objection_handling.what_not_to_say is required for every objection entry

7. Quality & Safety Architecture

7.1 Hallucination Prevention

  • All LLM synthesis grounded in ranked evidence chunks (max ~18, all cited)
  • INSUFFICIENT_EVIDENCE escape hatch: model omits rather than invents weak sections
  • Specificity over completeness: no category-level risks, no generic bullets
  • Fact/inference/hypothesis tracing: every claim labeled with epistemic confidence
  • Parallel quality-gate evaluator independently assesses section strength before release

7.2 Provider Failover & Resilience

  • Primary + fallback OpenAI-compatible API providers (configured via env vars)
  • executeWithOpenAIProviders() retries across all provider combinations on transient errors
  • Per-provider model name mapping (fallback may alias o3 to a different model ID)
  • Vercel Cron retry queue: every 5 minutes, re-runs stuck or failed requests

7.3 Data Isolation

  • Supabase Row-Level Security (RLS) enforces user-to-report isolation at the database layer
  • All semantic searches filtered by request_id — no cross-user data leakage possible
  • Auth middleware validates Supabase JWT on all routes

7.4 Graceful Degradation

  • Overlay failure does not fail the report — logged, surfaced as 'pending' only
  • Quality-gate partial sections shown with confidence indicator rather than suppressed entirely
  • If Firecrawl is unavailable, falls back to axios for direct web fetching
